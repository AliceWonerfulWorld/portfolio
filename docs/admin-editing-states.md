# 管理画面の編集・保存・公開状態（Issue #9）

> この文書はIssue #9時点の履歴です。現在の契約は [admin-platform.md](admin-platform.md)、画面は [admin-design.md](admin-design.md) を参照してください。旧一時編集画面の本番ルートとブラウザートークン認証は置き換えています。

## Issue #9時点の仕様

管理画面は一時編集とJSONエクスポート用。「一覧に一時反映」はReactの状態だけを更新し、永続保存・公開反映・画像保存を行わない。操作前の画面案内と操作後の `role="status"` にこの範囲を表示する。

- 入力途中: 元のフォーム内容との差分を検出。キャンセル、新規追加、別項目の編集前に破棄確認する。拒否した場合は入力を保持する。
- タブ切り替え: 両エディターを保持し、フォームと一時反映済みの一覧を失わない。
- 一時反映済み・JSON未出力: 公開とは別の状態として表示。ページ離脱の確認対象に含める。編集中は削除を無効化して編集対象の位置ずれを防ぐ。
- JSON出力: 一時反映済みの一覧のみを出力する。フォームの入力途中の内容や編集用indexは含めない。「ダウンロード開始」と案内し、保存完了とは表示しない。ファイルの保存・内容確認は利用者が行う。
- サイトを見る、ブラウザーの戻る／進む: React Routerのブロッカーで確認する。ログアウトも破棄確認を行い、拒否時は認証状態を保持する。
- 再読み込み、タブを閉じる、外部ページへの遷移: `beforeunload` でブラウザー標準の確認を求める。文言はブラウザーが決める。モバイルのアプリ強制終了等ではイベントの発火が保証されない。
- 認証確認中: 保護された画面では「ログイン状態を確認しています…」を表示し、確認完了後に遷移する。認証方式自体は変更しない。

## サーバー連携後のUI仕様

以下は将来の仕様であり、今回の実装ではない。

| 状態 | 表示と操作 | 読み上げ／失敗時の扱い |
| --- | --- | --- |
| 入力途中 | 「未保存の変更」。下書き保存と公開を別の操作にする | 離脱前に確認する |
| 保存中 | 「下書きを保存しています…」。重複送信を無効化 | aria-busyとrole=status。完了するまで入力内容を保持 |
| 保存成功 | サーバーの成功応答後に「下書き保存済み」と保存時刻を表示 | role=status。未保存フラグを解除する |
| 保存失敗 | 「保存できませんでした」と理由、再試行操作を表示 | role=alert。入力と未保存フラグを維持する |
| 下書き | 「下書き・未公開」。プレビューと公開操作を用意 | 保存成功を公開成功と扱わない |
| 公開中 | 「公開しています…」。重複操作を無効化 | role=status。公開完了を応答前に表示しない |
| 公開成功 | サーバー確認後に「公開済み」、公開時刻と公開ページの導線 | role=status。保存状態とは独立して更新 |
| 公開失敗 | 「公開できませんでした」。下書きを保持し再試行可能 | role=alert。公開済みの表示に変更しない |

画像アップロードは個別に処理中・成功・失敗を示す。認証失効や競合でも入力を保持し、再認証／再取得の導線を提示する。永続化・画像保存・サーバー認証は別の実装範囲。

## 旧画面の回帰確認（履歴）

`scripts/check-admin-browser.js` はローカル管理画面上で実行するブラウザー用検証。初期データの状態で開始し、確認ダイアログを一時的に模擬して16項目を検証する。JSONのBlobを検査し、テスト中の実ダウンロードは抑制する。テスト終了時はログアウトする。公開データは変更しない。

ローカル専用のテスト用認証状態で `/admin` を開き、次を実行する:

```sh
npx --no-install agent-browser --session portfolio-issue9 eval --stdin < scripts/check-admin-browser.js
```

ビルド・lint・既存の作品テストに加えて、戻る操作、認証済みの再読み込み、未認証時の遷移、390pxと1280pxの表示をブラウザーで確認する。
